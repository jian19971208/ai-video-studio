# Internal production guide

适用条件：自定义制作的review默认关闭，可按用户要求开启。关闭时不做内容审查、不抽取报告证据、不生成HTML，交付视频和请求参数；下载、文件完整性和基本播放检查仍做。本文的内容审查与HTML交付要求仅在启用审查或固定预设要求审查时适用，不反向强制开启自定义审查。

## 执行前

先执行[设置与前置检查](preflight.md)。默认方案、用户选择和真实能力检查是生成前步骤；所选配置改变后重新核验。

1. 先查workflow-list，解析所选已配置流程对应的manifest与guide；临时任务使用显式standalone。继承已有明确要求、预算及后端；按[配置规则](configuration.md)解析参数并使用该工作流绑定的具体接入profile；未绑定先展示接入选择。登记连接不会自动绑定工作流，已确认的绑定不反复问。
2. 按[能力与依赖](integrations/capabilities.md)核对本次需要的工具。技巧的通用/模型/节点/平台适用级别见[技巧目录](techniques/index.md)。尚未配置的能力给出具体网址与最短操作指引。已授权范围内继续独立工作；关键能力缺失时停在对应阶段，不静默换付费供应商或改变创意来源。
3. 选当前系统 `bin/` 内的 `avp` / `rh`，使用完整路径。无需 Python 或 Go；媒体探测/抽帧优先复用服务器或宿主能力，客户端FFmpeg为显式启用的可选项，见[工具命令](integrations/cli.md)。本包不携带模型权重、账号、商品素材或全量节点目录。
4. 接入指引：[RH](integrations/runninghub.md)、[自建 ComfyUI API](integrations/self-hosted-comfyui.md)、[生图与素材服务](integrations/image-and-materials.md)。SSH 属于可选维护能力，不是普通生成前提。
5. 使用 H3 时先发现并读取独立的 **`h3-prompt-writing` Skill**，再读其正确模式参考文件。依赖定位、官方地址和缺失处理见[提示词](techniques/prompt-writing/guide.md)。不凭记忆伪称已应用官方规范。

## 生产与恢复

按所选工作流获取素材 → 创意与分镜 → 审源图 → 生成 → 全片及问题帧审查 → 定向返修 → 后期 → 交付。每个阶段输出保存到任务目录；模板在[记录规范](workflows/records.md)。按所选流程固定方法运行，后端、素材与预算取实际绑定和输入；要求改变方法时先复制当前任务独立草稿，不覆盖预设。

- [真实节点图目录](techniques/graphs.md)提供脱敏、可参数化的历史执行图。先上传素材、绑定参数、核对现场节点/模型，再执行；技术执行成功与内容可用分开。
- 默认动态商品路线采用已审分镜/真实商品图＋REF，整段/拆段策略按[REF技巧](techniques/reference-to-video/guide.md)执行；单项或独立草稿可按明确用途选择FL/AG、白模、续接、LoRA；固定预设不临时加入这些方法。历史静态片和失败实验不能被称作稳定成功方法。
- 每个 job 固定一份回执。有 ID 查原 ID；提交结果不明先核查，不换 job 绕过。下载坏只重下，抽帧坏只重抽。未知费用保留预留；不得为检查接入另做付费生成。
- RH 原生工作流默认 RH 币；商业 API、跨平台改付费路线、追加预算另按用户授权。服务器队列忙时等待，不杀进程、不卸模型、不重启。批量与并发按资源和预算配置，连续视频的实际末状态依赖串行。
- [质量审查](techniques/quality-review/guide.md)同时看产品保真、自然运动、节奏与卖点；审查不了的维度写待审。未试听不写声音通过。不能靠静态商品盖片或叠化掩盖模型失败。
- 达到工作流停止条件后交付合格片或诚实的未通过结果；不为了预算剩余继续抽卡。可复用经验先写任务记录，更新发布见[维护规范](workflows/evolution.md)。

## 状态、单项与用户引导

按[使用引导](interaction.md)区分功能介绍、接入登记、方法操作和完整制作。单独调用某项技巧不执行上面整套广告流水线；所列整片顺序只适用于需要完整成片的任务。配置保存、连接通过、环境适配、执行成功和内容合格分别报告，不把其中一步包装成全部完成。用户未明确拒绝的建议配置项按持久清单提醒，用户明确不再提醒后不纠缠；任务必需缺项仍要说明。

## 产出与配置分离

开始制作前读取工作流output_directory，未选则先由用户选择。project --workflow NAME --task TASK使用保存目录，--output-dir用于本次临时位置；完整任务路径可显式--project。视频、素材、草稿、图、回执和审查全部进任务目录，配置根只保存路径设置与长期配置。不要把“可运行配置”当作已选输出位置。清理与存储见[规则](storage.md)。

## 成品流程运行

先接入，再选独立制作/工作流。固定流程只说明交付内容和各步执行位置，完成运行前检查；必需缺项停止、可省略缺项提前具体告知。不得再问是否修改分辨率、超分或后期策略。运行配置仅是环境与输出/内容绑定；不同设计复制独立流程。

## 本次制作数量

按[数量与预算](workflows/delivery-quantity.md)确认需要几个成品，可附预算上限。每条固定包含审查报告，不询问审查/返修模式，不自动付费返修。此规则优先于本文一般性返修顺序和“仅交合格片”的描述，内容问题如实交付报告；技术失败不计完成数。
