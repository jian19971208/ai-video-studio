# 模型、分辨率与对照参数

固定工作流调用本技巧时，以该流程的method/fixed_settings和项目快照为准，本页的其他路线供单项或独立草稿使用；不能据此临时换预设模型、技巧或流程。

- 适用级别：模型/硬件相关，不可跨模型照抄
- 前置能力：video.generate.reference
- 当前采用：按生产阶段配置；实用价值：4/5（项目内优先级，不是模型评分）。


制作基线从已验证的原生20步、match、无LoRA/Turbo开始。480/576用于创意与运动筛选；细小产品信息需要更高原生分辨率时在预算/显存允许下做768对照。不要把源200px格图放大称高信息输入。

match/max按现场定义取值，max不普遍更好且增加资源。量化编码器/扩散权重支持取决节点和设备；Windows/Mac运行CLI成功不等于当地能推H3。

研究时每次明确新假设和比较变量：同seed同源比较prompt、Guide数量或输入；跨REF/FL、编码器、服务器改变时标记多变量。记录实际运行时间、失败费用与返修，别只记挑中的秒数。

Turbo/LoRA在专项验证后使用，不暗中降步数或换加速模型来赶时效。扩展模型要补自己的提示词规范、输入限制、成功图与实际验收，不默认沿用H3采样帧公式。

## 操作步骤与产物

1. 先读取有效设置和所选服务的实际限制，分别写生成尺寸、交付尺寸、fps、时长、模型及采样配置。包内20步/match仅是H3已验证配方，换模型按新接口定义。
2. 对照[图资源](../graphs.md)的bindings逐项改Loader、宽高、采样长度、保留帧数、fps、音轨时长及Guide位置。当前H3样例15秒24fps留360、采样362；续接图有自己的规则，不套统一加2公式。
3. 核对设备量化格式/算子、显存与所选参数的历史/官方依据。缺资源先说明，可选调整需符合用户本次要求，不自动降步数或分辨率。
4. 做对照时固定商品、创意和可固定参数，写清这次改什么；跨后端或编码器变化如实记多变量。输出有效参数、适配证据和实际耗时成本。

**验收与失败处理**：下载后核对真实尺寸、fps、时长和保留帧数；生成成功但文件规格错，修映射/裁帧后按原因处理，不把参数记录当实际探测。

执行环境、输入绑定、任务恢复按[公共执行方法](../execution.md)；所需服务配置按[服务能力核验](../../integrations/service-capabilities.md)。
