# 自动化、预算、恢复与产能

- 适用级别：通用流程工程；费用按各适配器实回执
- 前置能力：media.probe
- 当前采用：核心；实用价值：5/5（项目内优先级，不是模型评分）。


任务记录保存输入、prompt、节点图、任务ID、执行与等待耗时、下载校验、审查、返修与费用。各端记录分开：RH币费用不能混入本地0币，也不拿钱包差额记项目成本。

同job回执先于提交保存；有ID只查同ID；超时无ID保留不明记录，核对平台历史后恢复，不删除回执换job重提。成本未知时保留预留，不能当0。确认失败并理解原因后才创建有新假设的变体。

并发仅用于独立镜头，受资源、已授权预算与平台配额共同限制。自建默认闲队列串行，远端API可配置并发；不自动取消别人的任务、卸模型或重启。监测若用户要求才设置，已有后台活着不重复开；完成/失败/需输入才通知，交付后关闭对应监测。

衡量真实价值：每条合格成片总费用、人工介入分钟、可用镜头率、返修次数、端到端周期。本地无RH费不等于硬件/电费免费；单次漂亮样片也不是跨商品稳定量产证据。

固定风格生产优先复用上次合格的设计方法、输入规范与技术图，但每次继续源图与成片验收。批量自动化使用工作流固定素材策略，无需人工每次手填创意参数。

## 操作步骤与产物

1. 开始前解析工作流与接入绑定、设置和授权预算，登记每一步执行方及依赖。RH币、钱包币种和自建算力分开记账，现有余额不当成自动消费许可。
2. 提交前检查同job原回执和runner/平台队列。首次提交保存请求意图，返回后立即保存ID；超时不明则核对原任务，不生成新job兜底。
3. 持续查询同ID，成功取实际输出和费用，记录云执行、等待、传输及总耗时。失败读取服务错误/历史，定位上传、模型、资源或输出阶段；未结费保留预留。
4. 同一RH task的整任务consumeCoins重复数据只记max一次，不求和；钱包费用按该接口官方费用字段/账单记录，区分总项与子项避免重复。自建算力不写RH支出，外部付费节点另记。
5. 下载校验与内容审查后更新项目状态；独立任务才可按配额并发，有实际前段依赖的续接串行。结束给合格率、返修、人工介入和总成本，已有监测按用户要求结束。

**失败处理**：恢复同回执，不清队列、不重启服务；预算和内容门禁分别处理，执行成功不自动等于可交付。

执行环境、输入绑定、任务恢复按[公共执行方法](../execution.md)；所需服务配置按[服务能力核验](../../integrations/service-capabilities.md)。
