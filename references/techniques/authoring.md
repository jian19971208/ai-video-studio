# Add or update a technique

每项技术采用同一说明格式：用途与触发条件；适用级别（通用/模型/ComfyUI节点/平台）；能力依赖；输入输出；执行步骤；适用与不适用范围；验收；实测证据与日期。

需要执行图则附 `graph.json`、`defaults.json`、`manifest.json`；从真实执行图脱敏，用变量替换商品、上传名、prompt、seed、输出前缀。不复制私人素材、Key、签名URL或机器路径。模型名保留已验证值并要求现场核对。

明确证据状态：proposed / structurally-validated / executed / content-accepted / production-validated。技术运行成功不代表创意通过，某一场景有效不升格为普遍定律。平台特有能力写明平台和收费；图像设计必须声明生图依赖。

更新catalog与调用工作流的依赖/版本，保留旧版任务记录。先记录试验；用户要求维护发布时再升级技能。高风险新技术不自动进入所有生产工作流。

## 操作说明完成标准

每项guide除了结论必须写“操作步骤与产物”：输入是什么、如何选路线、具体操作及关键参数、输出给谁、怎样验收和失败恢复。公共上传/绑定/提交引用[执行方法](execution.md)，服务依赖引用[能力核验](../integrations/service-capabilities.md)，不要重复大段公共操作。

有图时链接manifest并解释必要变量、帧范围和输出限制；没图的接口写明需要实际适配，不虚构已实现节点。方法通用、历史跑通、包内附图、当前服务具备四种状态分开。证据来源与未经证明的局限保留在原技巧，不为凑完整而把所有模型写成支持。

单项使用时只检查所选分支依赖，不继承某个广告工作流的完整requires；指南须能独立执行该操作。操作方法、包内图、后端适配器和当前服务能力逐项写清，缺任何一层不以“支持这个技巧”冒充开箱即用。交互与状态引用[使用引导](../interaction.md)，不要在每项技巧复制平台接入对话。

技巧默认在techniques/config.json的techniques.<配置名>保存，method标识方法，settings定义选项和含义，通过technique-save/technique-settings读写。写清单项调用怎样合并本次覆盖，以及哪些字段供工作流technique_bindings引用；未实现的配置字段不能当实际节点能力。敏感认证归integrations，项目产物不放配置目录。

配置扩展按[技巧配置](configuration.md)：方法ID与具名配置分离，说明可选provider和方法设置；定义能否继承工作流、是否必须与主生成接入相同，以及允许独立处理端的情况。新增方法不自动注册用户配置；工作流通过technique_requirements声明依赖，通过部署配置technique_profiles选方案。只需说明默认方法意图，不复制作者资源路径。

## 草稿与收录约束

制作方法在作者定义中固定，运行配置只保存环境绑定与内容输入。创建/复制先放当前任务；明确确认且同版本校验、试产审查通过后才登记。Skill收录需明确发布授权；遵循[工作流生命周期](../workflows/lifecycle.md)。

## 被工作流引用时的依赖归类

技巧声明完成自身操作所需的真实能力；是否影响整条流程出片，由调用工作流决定。普通视频制作中的超分等增强缺少或失败，返回具体原因、启用条件与原输入产物，供工作流交付原片；单项超分任务则不能跳过超分冒充成功。不要把某技巧的模型、后期工具或试听依赖无条件提升为所有视频流程的顶层必需项。
