# FL与AddGuide

- 适用级别：H3模型/ComfyUI节点专属；不是所有平台都开放
- 前置能力：video.generate.keyframes, video.guide.h3, image.inspect
- 当前采用：按明确需求选用；实用价值：3/5（项目内优先级，不是模型评分）。


纯FL：fl2va权重＋MiniMaxH3ImageToVideo＋AddGuide链，无REF槽；REF+AG：ref2va权重＋真实REF槽＋额外Guide。保留准确标记，不把混合图当纯FL对照。模板见 `h3-fl-rh/`、`h3-ref-ag-local/`。

不同首尾可推动构图过渡，但背景、地面、阴影、相机关系必须一致。反复同图首尾/密集同图容易冻结，首尾约束并不保证每一帧原图级一致、也不保证均匀速度。两个独立生图端帧曾引入粗黑地缝、放大主导或首尾弱动。

图片Guide适用于确需状态控制的少动作片段；复杂开箱、抛接、弯折不默认堆AG。成对F-1/F可试收紧切点，但不是硬剪辑时钟。不同prompt/seed/编码器/后端的比较标记为工作流对照，别伪称模型单因素。

官方节点还可接短视频帧组或音频。22帧Guide需实际运动末段与正确frame_idx，音频需实际编码链；不能把视频当单图、把音频波形相关性当试听通过。缺对应成功图时先查现场schema和实际模板，不猜新增端口。

质感与运动是验收项：几何更受控但像图片，就不适合动态广告。用户不要求精确端帧时优先尝试REF自然表达，避免为技术组合而组合。

## 操作步骤与产物

1. 先写明需要控制的状态和时刻，再决定纯FL还是REF+AG。准备实际不同且背景关系一致的端帧并审图；没有必要状态约束时不额外加Guide。
2. 分别参考[h3-fl-rh](h3-fl-rh/manifest.json)、[h3-ref-ag-local](h3-ref-ag-local/manifest.json)，按[公共执行方法](../execution.md)核对权重、节点链、参考槽与现场schema。图片/视频/音频只连接该节点实际支持的输入。
3. 记录每个Guide的文件、类型、frame_idx及在采样时间轴的目的；例如包内6秒样例是146采样、保留144，末Guide145是采样索引，不应承诺交付143帧精确复制原图。更换时长同时更新采样、Guide、裁帧与音轨。
4. 运行后查每个锚点前后数帧和区间中段，查看是否冻结、速度突变、融化、扫光或部件增减，并正常播放；输出Guide表、原片与review。

**失败处理**：删减冲突条件或重做不一致端帧；若受控但僵硬，记录不适合该镜头，在已授权方案内考虑REF。不得把锚点数量增加当成默认返修。

执行环境、输入绑定、任务恢复按[公共执行方法](../execution.md)；所需服务配置按[服务能力核验](../../integrations/service-capabilities.md)。
