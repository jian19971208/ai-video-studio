# 面向用户的审查报告

报告是帮助用户判断成片问题的，不是展示检查过程。交付一份中文 HTML，直接打开即可看到原商品与问题画面的对比。具体审查操作仍按[质量审查技巧](guide.md)，不要因此减少内部检查。

## 固定呈现顺序

1. **结论**：一两句话说明主要问题和对使用的影响。没有发现明显问题就直接写，不为填报告制造问题。
2. **问题对比**：每个实际问题一张对比卡，按影响大小排序。同类反复出现的问题合并，注明时间段，不铺满所有帧。
3. **未完成项**：仅有实际未完成项时用一行说明，例如“声音待试听；未正常速度完整播放”。缺少增强时简短说明未做内容、原因和启用条件。

无明显问题时，一句结论加一组代表性的原商品/成片对照即可，不输出空的问题列表。自定义任务没有商品参考时，使用用户提供的对应原始参考；没有可比较的参考则展示实际问题证据，明确未提供参考，不编造商品原图。

## 每张问题对比卡

| 内容 | 要求 |
| --- | --- |
| 标题 | 具体问题与出现时间，例如“5.0 秒：旋钮 Logo 图案变化” |
| 左侧 | 用户提供的真实商品图，选相同部位和尽量接近的视角，标签“原商品” |
| 右侧 | 最终交付视频中的实际问题画面，标签“成片 · 5.0 秒” |
| 对齐与标记 | 同一部位采用接近的显示比例，可放大裁切；用红框、箭头或 HTML 叠层标出对应位置，保持真实像素和原始宽高比 |
| 说明 | 一两句话描述原来是什么、成片变成什么、实际影响；不能只写“保真不足” |

图片用 data URI 内嵌 HTML，报告离线可看；大图按实际阅读尺寸压缩，不把整套原尺寸抽帧全部塞进去。必要时一张完整构图定位加局部对比，避免只有局部无法辨认位置。

不能用前期生图当“原商品”。前期图已引入错误时，说明错误来源；需要时补一张“设计参考”，仍保留真实商品与成片对比。结构问题展示可见差异，不能通过拉伸、改色、美化或 AI 重绘证据图。动作、穿模和衔接问题可用少量相邻问题帧展示过程，但不改成整片联系表。

## 不在交付报告展示

- 规格与检查范围大表：编码、文件大小、精细帧率、帧数、MP4样本表和逐帧解码实现。
- 抽帧间隔、抽帧数量、整片时间线取样证据、整页联系表和连续无问题截图。
- 节点参数、步数、任务轮询、采样方法、排查过程、自建推理耗时或费用明细大表。
- 批量创意差异化的自证段落、流程执行说明和无问题的检查项清单。

这些信息保留在内部审查记录及实际请求参数文件。技术异常确实影响播放时，把它作为一个具体问题简短报告；用户另外要求规格、耗时或费用时再按需提供。

## 生成报告前核对

- 每个可见商品问题都有真实原图与最终成片问题画面的并排证据，时间对应正确。
- 报告依据实际检查，图片缺失或无法观察时标明该项待核，不写成已确认问题或通过。
- 没有“时间线取样证据”等内部过程章节；未审项目如实用简短文字保留。
- 同一交付目录仍只有成片、此 HTML、实际请求参数；超分成功才另附原片。
