# 程序化剪辑、文字与品牌收束

固定工作流调用本技巧时，以该流程的method/fixed_settings和项目快照为准，本页的其他路线供单项或独立草稿使用；不能据此临时换预设模型、技巧或流程。

- 适用级别：通用方法；默认所选服务器/云端的已验证编辑能力，客户端编辑显式可选
- 前置能力：media.edit, media.probe
- 当前采用：常规；实用价值：4/5（项目内优先级，不是模型评分）。


先确定输入是完整已审视频还是经批准的分段素材。完整视频可只做字幕、Logo、音轨和必要头尾处理；剪辑阶段不要求拆片或拼接。需要组合时再写edit-plan：每段源文件、从第几帧取几帧、fps、顺序、音轨时间映射、文字/Logo。完整保真与镜头节奏合格才收段。每个切点看前后数帧及正常播放，统一色调、运动方向与音量。

`three-shot-assembly-rh/`仅用于实际需要分段合成的任务，不作为短视频默认生成路线。它是实际验证过的三视频裁帧+ImageBatch+连续音轨+淡入出+CreateVideo/SaveVideo图。按模型素材实际帧数与尺寸改参数，三段帧数之和/fps必须等于音轨长度。该图在本地是否兼容以现场schema为准，不能把RH验证冒称双端验证。

少量短镜可原生图完成。长/高分辨率拼接容易中间张量占显存：优先已编码文件拼接节点，或用户允许地点的FFmpeg/MLT。所有后期必须服从用户“仅RH”“仅本地”等运行地点要求，不为方便暗中下载到别处处理。

品牌字标与卖点标题可在后期用真实Logo/确定字体叠加；介绍线必须指对部件。生成文字不准确时不得靠超分修字。独立片尾Logo是正常包装；不能以静态产品覆盖坏视频再当生成保真验证。

Shotcut是软件名（不是shortcut），MLT/FFmpeg适合程序化常规后期；剪映手工包装和达芬奇/Fusion复杂合成可作为另行适配，不宣称本包有稳定GUI自动操作。后期能力是接入项，工作流不绑某个编辑器。


## 可选增强与环境适配

成品流程由自己的固定步骤决定做哪些编辑、是否允许缺失时省略；不能用运行时post_edit开关改变。商品宣传流程仅在已有服务与资产支持时叠加真实Logo和一个卖点字幕，缺失须生成前预告，其他核心验收照常。单项或独立设计可以按自己的目标选择编辑方法。

优先同一服务器/云端的编辑图或API，遵守用户指定执行地点。本机FFmpeg/MLT不是默认依赖；明确选择且已配置才使用[可选本机工具](../../integrations/local-media.md)。缺少这种可选工具不影响核心生成。完整原片已经满足目标时，后期也可以off。

## 操作步骤与产物

1. 输入完整已审原片或明确批准的分段，写edit-plan：每段文件/帧范围、输出画幅/fps、字幕文字和显示时间、Logo位置尺寸、音轨映射。整片包装不需要先拆成多段生成。
2. 确认服务具体支持裁切、拼接、字型/字体、透明Logo、音轨和需要的转场；RH三镜示例见[实际图](three-shot-assembly-rh/manifest.json)。该图不自动具备字幕/Logo，需现场增加已验证节点或另用有该能力的处理服务。
3. 在所选执行地上传素材并绑定参数；多段按源帧率计算帧数总和，等比例构图。客户端明确已配置时可按[本机工具](../../integrations/local-media.md)使用avp edit；不安装软件，不擅自把服务端任务搬到客户端。
4. 输出新文件、保留原片和处理计划，播放切点、文字出现/消失和片尾，完整解码并核对规格；字幕安全边距和指示线对准真实部件。超分前后哪版包装按服务支持确定并记录。

**失败处理**：缺流程明确可省略的包装，生成前具体告知后按定义回退，必要字幕/品牌效果缺能力列明阻塞；编辑失败只恢复编辑任务，不重生成合格视频。不要以静态产品图覆盖坏视频伪造保真。

执行环境、输入绑定、任务恢复按[公共执行方法](../execution.md)；所需服务配置按[服务能力核验](../../integrations/service-capabilities.md)。

editing单项方法可以独立保存设置；成品流程只允许匹配固定操作与执行域，不映射为使用者可调开关。实际字幕/Logo/音轨能力需分别核验。
