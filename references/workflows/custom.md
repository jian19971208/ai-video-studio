# 自定义制作工作流

[入口定义](custom-production.json)固定工作过程，具体制作方法根据用户需求设计。它是一条规划和制作工作流，不是预先固定15秒/H3/超分的商品宣传配方，也不是已有一张可直接付费生成的节点图。

## 工作过程

1. 理解目标、已有素材、数量和输出位置。素材可由用户提供，也可按目标安排获取；不要统一强制用户先填商品文件夹、图片来源或广告卖点。
2. 设计本次制作方案：创意、镜头、模型、时长、尺寸、声音及必要后期/超分。按目标只补影响执行的缺项，调用[技巧目录](../techniques/index.md)中相关能力，不将所有技巧都加入方案。
3. 根据本次方案调用[工作流接入选择](integration-selection.md)。每次按selection_policy确定本次用哪套；只有用户明确关闭该工作流提示且绑定有效才自动沿用；先确定方案支持的平台，不在接入登记阶段替当前任务选择。多端确实有用时按步骤明确绑定，不默认混用。
4. 在当前任务编写实际执行manifest与节点图，参照[步骤契约](step-contract.md)、[扩展规范](authoring.md)、[前检](../preflight.md)。每一步有实际输入/输出、能力、执行位置和恢复方法。实际计划确定后固定为本次方案，不在生成中自行改方法。
5. 按用户授权执行、查询原任务和下载。每条视频给成品及审查报告；无法试听标待试听，不因为该项要求复制或另行批准。常规内容问题如实报告，不擅自反复付费重生成。
6. 按[交付记录](records.md)输出成片、HTML报告、合并实际请求参数；实际有超分才附原片。单独做超分/剪辑/审查也可走此流程，只执行所需步骤、交付其实际产物，不强加完整广告链。

## 任务与复用

`workflow-describe --template custom-production`列出本过程，`workflow-targets`按本次方案的支持范围辅助选择。`project --workflow custom-production`只建立规划项目，不填假的媒体尺寸、不提交任务、不把规划入口当作ready。

Agent在规划项目内生成真正任务执行定义，完成参数/能力/图校验，再用显式standalone项目执行：`project --workflow-file TASK/workflows/ID/ID.json --mode standalone --backend BACKEND --profile PROFILE --project TASK/internal-execution`。具体路径由任务输出根派生，不硬编码作者路径。实际产物归入规划项目delivery，内部执行目录不向用户交付。

当前任务设计与把它保存为常用预设是两件事。仅用户明确要求长期登记并完成验证后，按[生命周期](lifecycle.md)保存；进入Skill另需明确收录授权，不因一次自定义制作自动扩充公共预设。创建新草稿用workflow-new；未指定来源时是未完成的创作骨架，需清除不适用的继承步骤、模型和平台约束，按本次目标完整编排后才执行。

本次执行接入按[选择与提示配置](integration-selection.md)管理：默认每次确认，只有用户明确不再询问才保存关闭项与有效绑定；在接入确定前不进入素材收集，不以历史绑定跳过。
