# 自定义制作工作流

[入口定义](custom-production.json)固定制作过程，不固定创作配方。已明确自定义、具体人物剧情/动画/效果或单项处理时进入本流程。仅说“做视频/创作一个新视频”且上下文不足以判断时，先咨询使用现成模板还是自定义，不擅自选择本流程。明确选择商品宣传预设则走其固定流程。

## 每个新对话只提醒一次

在当前对话首次进入自定义制作、介绍方案时，简短提醒：“默认配置可以修改：只改本次直接说；想以后都沿用，请说‘以后默认……’。”同一对话后续继续制作、追加任务、返修或查询进度不重复。新对话首次使用再提醒；只问功能或还没选择制作方式时不抢先塞入。

提醒是否已说过根据当前对话记录或宿主会话状态判断，不存成全局“已提醒”导致新对话也不提示。频率由入口定义intake_policy.default_configuration_notice声明。它不等同于接入selection_policy：不再提醒默认可修改，不代表自动选服务器。

## 先选接入，再展示默认与可选项

1. 按[接入选择](integration-selection.md)先确定自建ComfyUI或RH及具名配置；用户本次已明确则复用。接入确定前不替用户定模型或收一串素材。
2. 初次只读核对接入连通、模型/节点清单、费用路线和宿主工具，作为展示选项的依据。这里只能说明已发现哪些资源，不代表最终需求已可执行。自建列真实库存；RH区分RH币和钱包路线，未确认接口的服务不称可执行。
3. 先围绕用户想表达的内容沟通。用户不需要先选模型或技巧；Agent在交流中逐步理解目标、参考、风格、动作和时长，提出有理由的建议，结合反馈安排节点和提示词。用户希望简单或已经说清怎么做，就直接整理方案，不强制勾选功能、不重复确认。

### 开场顺序必须完整

选定执行接入后，先介绍“自定义默认直接生成”：根据用户描述编排文字镜头和提示词，按有效默认和已有参考出片；默认交付视频MP4及实际请求参数JSON，不提前生图、不超分、不做内容审查，所以不附审查报告。然后展示下面的默认安排表。

表格之后明确给出技巧入口：“也可以先看看有哪些技巧：你可以说‘列出技巧’，我会说明各自能做什么、适合什么场景，再结合你的需求安排。想简单制作，直接告诉我内容即可。”不能只泛泛说“需要时可安排”而漏掉可查看技巧清单的能力，也不要求先看完清单才能制作。

### 开场：一张默认安排表，技巧另作简短建议

先围绕用户实际目标沟通。介绍默认时只放一张“默认会怎么做、得到什么”的表，不把技巧清单塞进表里，也不拆第二张技巧表。表中用本次有效值：当前要求优先于已保存默认，已保存默认优先于内置默认。

| 项目 | 没有特殊要求时的默认安排 |
| --- | --- |
| 视频生成 | MiniMax H3，768P、15秒、9:16竖屏、24fps |
| 制作过程 | 根据对话设计镜头，使用已有参考，完成视频生成 |
| 提示词与参考对应 | 使用H3官方提示词Skill整理提示词，并对照实际素材输入；本机已有时每份提示词必用，不是可选开关 |
| 声音 | 保留模型原音轨 |
| 额外处理 | 不提前生成图片分镜、不超分、不做内容质量审查 |
| 交付 | 视频和实际请求参数；检查下载完整性与基本可播放性 |

表格前后简短说明：“这是默认起点。你可以直接描述想要的内容，我们边聊边确定，我会按实际需求安排；有明确要求就按你的要求调整。”不要要求用户先决定模型或逐行确认。仅在每个新对话首次提醒可修改长期默认。

表格之后，用一小段介绍可能有用的技巧，例如：“需要时可以先生成图片分镜确定画面，用视频参考帮助描述动作/运镜，或做长视频续接、超分、质量审查。这些只是可能采用的方法，不是必做步骤，也不会因为介绍了就全部执行。你可以点名要求，也可以提出其他效果，我会结合需求研究安排。”

按当前题材挑相关建议，不每次照抄所有方法；用户不用先选完技术菜单。已有明确上下文或直接做指令时，简短总结采用方案并推进，不重新问“想拍什么”。需要增加生图、超分、审查等可选步骤时提出具体建议和影响，按用户选择或已有明确授权启用，不因工具可用就自动开启。

### 说到的设计必须落实到实际任务

不能只口头声称“根据需求设计”，随后忽略当前要求直接提交模板。执行Agent需要在当前任务已有plan/manifest中记录：

1. **本次实际要求与有效配置**：从当前对话提取目标、主体/参考、情节与效果、规格及明确开关，并保留来源；本次B覆盖以前默认A。
2. **要求到方法的对应**：采用哪些技巧、为什么；用户未开启的图片分镜、超分、审查不插入。需要新方法时研究实际节点和文档，记录尚待核实的环节。
3. **方法到请求的对应**：所选平台、模型、参考槽与素材用途、实际节点和连线、尺寸/时长/音轨参数、最终提示词；直接生成时允许复用适用REF骨架，但内容和有效参数必须按本次要求落实。
4. **提交前核对**：将实际请求与上面的要求、配置和步骤对照。发现仍是旧规格、参考未连接、提示词遗漏关键剧情或加入关闭步骤时先修正，再做最终平台校验。结构检查不能代替对照剧情和参考用途。

这些是实际执行Agent必须完成的工作，不是让用户填写的表，也不新增一堆交付文件。复用当前任务记录即可。用户后续改变要求时同步修改计划与相关图/提示词，再核验受影响项，不只修改聊天说明或重新描述同一旧请求。

### 最终需求确定后的执行前核验

规划完本次内容、模型、模式、尺寸、时长、参考输入及增强步骤后，再按[前检](../preflight.md)核验所选接入。检查实际节点图与模型权重/编码器/VAE、参考槽和文件格式、精确尺寸和长度范围、资源与队列、费用授权，以及启用的后期/超分能力。关闭的图片分镜和审查不加入必需依赖。

保存与最终设置一致的能力证据；需求/参数/接入变化则使旧的相关核验失效并重新检查。初始连通和库存不能代替本次检查；不靠付费试跑核验。不支持时先说明具体缺项及可行替代，不能静默降清晰度、改画幅或切换计费路线。仅在最终核心方案有依据可执行后提交；不把方案提出本身当成已获资源保证。


H3缺失、768P不支持、资源不足或费用超出授权时具体告知并提出方案，不静默降成576P或切钱包。可选增强缺失/失败按核心出片原则告知并回退，不自动安装或收费测试。

## 按需查看技巧

开场简短说明：“想了解有哪些做法，可以说‘列出技巧’，也可以让我按你的需求推荐。”不在每轮对话重复目录。用户问时通过`technique-list`读取当前真实目录；按名称、用途、适合的场景、当前能力条件介绍。需要某项细节时`technique-describe --id ID`读取其guide。用户只问技巧时直接介绍用途，不借机要求素材或启动制作。内部执行约束不向用户复述为“查看目录不会开启生图”等话。

当前接入未检查的项目写“待核对”，能用的结论需要已有实际证据；不能把技巧目录条目当已安装功能。用户只想了解方法时直接解释，实际采用时再核验相应工具和节点。

## 建议清单不限制自定义需求

默认配置和技巧选项只是给用户的起点，不是能力白名单。用户可以提出未列出的效果、方法或此前没见过的技巧；先理解目标，不因目录没有对应条目就拒绝，也不要求用户把想法套进现成选项。

已有技巧适合就复用；没有现成方法时，查询所选平台实际节点、官方文档与可用工具，必要时使用当前宿主的检索能力研究做法，设计新的组合或任务内实现。模型、节点和接口参数仍以实际定义为依据，不凭空捏造。已知模板不覆盖某种效果，不等于平台做不到。

先在当前任务中探索和校验可行方案，未验证的方法明确标为待验证，按已有生成/费用授权尝试。新增服务、模型安装、平台变更或超出授权的费用，先说明需要什么；已有授权足够就继续，不为常规搭图反复询问。现有平台确实缺能力时，说明具体限制和可行替代。

新方法的图、提示词和结果留在本次任务，可根据反馈继续修改；未经用户要求，不自动安装新Skill或将实验写入公共技巧库。仅MiniMax H3参考续接是当前内置长视频方案的实现范围，不是对其他自定义研究需求的永久禁令。

## 可选技巧怎样展示

根据沟通中的实际需求，从[技巧目录](../techniques/index.md)挑有价值的方法，说明为何适合、增加什么步骤及费用/时间影响，不堆节点名，不让用户先逐项选完再开始理解内容。图片分镜提前设计始终在可选清单中出现并说明当前开关；动作/镜头参考在有动作需求时介绍，长视频、超分、质量审查按需求介绍。用户可以组合选择，不只允许“简单/复杂”二选一。可用范围取当前平台与工具检查结果；缺能力的技巧如值得提示就注明需要补什么，不说成已经可以直接执行。

`storyboard_images=false`时，仍根据剧情编排文字镜头和提示词，并使用用户已经提供的图片；不调用生图、不要求确认新图片分镜、不把生图能力当出片依赖。用户明确要求先看设计图或先出图片分镜时，本次覆盖为true；仅有“设计分镜”的笼统说法不擅自解释为必须付费生图。开启后引用[分镜技巧](../techniques/storyboarding/guide.md)，不在本流程重写操作方法。

## 两个平台怎么执行

- **自建**：按[ComfyUI接入](../integrations/self-hosted-comfyui.md)查真实模型与节点，读取[公共搭图方法](../techniques/execution.md)，核对参考槽、尺寸、时长、连线和上传文件名，再按[命令](../integrations/cli.md)准备、提交、查询及下载。
- **RH**：按[RH接入](../integrations/runninghub.md)核对所选凭据、计费路线、节点和执行入口。原生算力通常用RH币；商业模型通常走钱包，图内商业节点可能另扣钱包。币种按实际账户，不统一叫美元。钱包路线需要本次费用授权，不因有Key和余额就自动执行。实际上传后填云端引用，校验再提交；不复用自建的HTTP包装。

有[历史图模板](../techniques/graphs.md)优先复用并按当前平台适配；没有图就按实际节点定义和文档搭建，不猜端口或模型名。商业服务尚无实际执行入口时如实说明未接通，不伪装可执行。

## 长视频

超过默认15秒或单次模型时长限制时，推荐两条路线：

- **分段生成后拼接**：适合多场景、多镜头，引用[剪辑技巧](../techniques/editing/guide.md)处理接点和音轨。
- **MiniMax H3视频参考续接**：上一段完成后，取实际末段视频作下一段REF输入，延续动作场景，再组合成长片；引用[接续技巧](../techniques/video-continuation/guide.md)。

当前模型参考续接只支持MiniMax H3 REF视频输入，不扩展其他模型续接或AG，不宣称存在独立同名节点。续接不是单次无限时长；每段核对实际输入/时长限制与输出，依赖上一段真实末状态时串行。

用户指定路线则采用；未指定可按内容推荐“多场景优先拼接、连续动作优先参考续接”，不把复杂节点选择丢给用户。拼接能力缺失时提前说明，不交若干片段冒充完整长片。

## 技巧与实际方案

先读[技巧目录](../techniques/index.md)，再读适用guide以及所需manifest/defaults/graph。文字分镜、参考、运镜、提示词、声音和审查按需求引用；图片生图分镜只有storyboard_images=true才执行；不是只读官方提示词就跳过其他适用技巧，也不是全部堆上。所有H3生成提示词（包括修改、续接和批量版本）必须使用本机已安装的独立h3-prompt-writing及对应模式指南，核对实际参考标签/槽位；它不受storyboard_images和review开关影响。

根据有效配置、创意和素材，在当前任务生成真实执行定义与节点图；按[步骤契约](step-contract.md)、[前检](../preflight.md)校验，再建立standalone执行项目。单项处理只取相关设置，不强加15秒广告全流程。

## 默认配置与本次覆盖

优先级：**当前上下文中最新且明确的用户要求 > 该具名自定义工作流已保存默认 > 内置默认**。之前说默认A，这次说B，本次就是B；只覆盖发生变化的项，不要求用户重选其余配置。`workflow-describe --template custom-production`返回内置/有效默认及来源。用户只改本次时不更改长期设置；明确说“以后默认……”才用`workflow-configure --name NAME --template custom-production --settings FILE`保存。配置仍在系统AIVideoStudio/workflows/config.json的workflows.NAME.custom_defaults，Agent代为操作，不让用户编辑JSON。

`project --workflow custom-production --settings TASK/overrides.json`记录本次有效配置和来源，可省略--settings沿用默认；不增加单独参数确认门。任务快照不算新配置目录。规划入口本身不是节点执行图，不直接提交，ready仍为false。执行接入仍按独立selection_policy选择，不用默认模型推断平台。

不满意时在当前任务调整参考、节点和提示词，保留旧版与回执，不强制复制成新的长期工作流。用户要求修改可继续制作，但不自动付费重抽；已有ID查原任务，长期登记按[生命周期](lifecycle.md)另办。

交付按[记录规范](records.md)：review=false默认只交成片与实际参数，不生成审查报告、不为报告抽帧。review=true时才按[图文对比报告](../techniques/quality-review/report-format.md)审查并附HTML，未试听如实注明。超分成功另附原片。下载、文件完整性和基本可播放性仍检查，但不称为人物、动作等内容已通过。用户单独要求“审查这个视频”就是本次review=true，不被默认关闭覆盖。
