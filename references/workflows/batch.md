# Batch production

批量是重复运行用户选定的完整工作流，不是新增一种视频创意预设。用户只需说明采用的流程、素材来源或筛选范围、数量，以及已有的制作设置与预算；不要再次要求填写流程已固定的创意来源或生图方式。

1. 从工作流素材策略生成本批条目；每项用稳定item ID和独立项目目录。素材来源可以手动目录、部门云盘或流程自行检索，不统一限定为目录。
2. 本批固定沿用所选流程的方法、模型、尺寸与时长；超分与包装完全按固定流程，无运行开关。要改方法先复制当前任务独立工作流，不能借批量改原预设。环境能力记录只在同后端/同profile/同URL且24小时内复用；每个新执行图仍prepare，并刷新节点定义。
3. 自建服务默认逐项提交，保留各item→job→prompt_id，先恢复已有任务。用户要求并发时再按已验证资源安排，不同时盲目塞入多条大显存任务。
4. 每项完整执行源图审查、生成审查、有限返修与交付；缺可选增强记skipped后继续。必需能力或提交结果不明时停在对应项，保留已完成结果。
5. 批次记录batch.json包含item ID、项目目录、状态、输出、失败原因和实际成本。重入按记录补未完成阶段，不重跑已完成项。批量次数不扩大总预算和返修上限。

这是Agent编排规则，Go工具负责各次确定的API操作。定时运行需宿主自动化或用户已有调度服务，不声称安装Skill就有常驻调度器。


批量每条新任务按[配置规则](../configuration.md)解析并固定有效选项；同一批次要保持统一时使用首项已确认快照，不在批次中途重新读取变化的全局默认。每条工作流需明确绑定接入，不能把“可用服务器”当“已选服务器”。

批次开始合并检查接入与必要缺项一次，不为每个商品重复索取名称、Key或已确认参数；处理中若认证/服务变化再复查。预算按整批上限和实际币种核算，缺少共享Key不阻断已选RH币路线，但需要商业服务的步骤仍须接入。单项失败是否继续其他独立项遵循该流程stop，不自动扩大批次或另找付费服务。

批次使用所选工作流已保存的输出根，每项独立任务目录；没有选择时先集中询问。更换本批输出位置只写批次及各任务快照，不移动旧产出或修改长期选择。配置重置不删除任何批次产出。
