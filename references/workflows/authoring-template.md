# 成品工作流设计模板

按[制作规范](authoring.md)由创作者填完。运行者提供内容输入、成品数量与执行接入，不承担技术配置决策。

| 设计项 | 作者必须写清 |
| --- | --- |
| 核心成品 | 用途、内容方法、固定模型/模式、生成尺寸、时长、帧率；什么结果算完成核心制作 |
| 最小依赖 | 缺失就不能出核心成片的接入、模型/节点、输入及文件输出条件；仅这些进入顶层requires |
| 素材策略 | 手动输入、固定来源或自主取得；额外生图是否可回退到现有素材；公共方法引用技巧 |
| 增强方案 | 具体超分、字幕/Logo、声音或编辑操作及执行端；方法和目标由作者固定，不提供开关菜单 |
| 增强回退 | 每项缺失/运行失败均skip-and-report，定义on_skip指向的已有产物、具体原因及启用条件；原片仍可交付 |
| 步骤契约 | ID、输入依赖、操作、执行位置、能力、产物、验收、失败及恢复，按[步骤契约](step-contract.md)填写 |
| 提前核验 | 选接入后、收素材前检查核心生成；增强缺失只告知，不阻塞；不靠付费测试证明已接入 |
| 接入选择 | 声明支持平台；每次确定本次配置，只有用户明确不再询问才保存该工作流绑定和关闭提醒 |
| 环境与交接 | 具名服务、跨端传输、费用归属、同ID恢复；无作者机器路径、Key或默认SSH/本机软件假设 |
| 交付 | 同目录成品视频、HTML报告、实际请求参数；超分成功另附原片；报告列明未做项目、原因和补齐条件 |
| 验证 | 核心依赖缺失会阻断；增强缺失/失败能交付；固定参数不被覆盖；授权内试产与质量/成本证据 |

JSON固定execution_locked、recipe_locked，parameters和technique_bindings为空，生产方法写入fixed。交付目标区分原片规格与可选增强规格，不能用目标2K重新阻塞原片。改变核心方法时复制新定义；通用操作只引用技巧。登记与发布见[生命周期](lifecycle.md)。
