# 固定工作流运行前检查

## 说明交付，再检查环境

接入完成且选定工作流后，读取workflow-describe。简短说明固定内容和交付规格，按execution_plan检查各步骤的执行位置、组件与实际能力。没有制作参数选择；分辨率、后期和超分均按定义，不问用户改哪项。

| 检查对象 | 核对内容 |
| --- | --- |
| 接入与位置 | API/认证、明确绑定、host/主接入/自建/云端是否符合各步定义；未绑定只补该接入 |
| 图片与素材 | 源素材可读、参考生图与看图能力；先审商品，不用文字模型冒充生图 |
| 固定生成 | 模型/编码器/VAE/节点、参考槽、固定尺寸与时长、显存/队列；H3读独立官方提示词Skill |
| 具体处理 | 按流程检查Logo、文字、音轨、超分等实际操作，不以“media.edit存在”代替所有编辑能力 |
| 输出与审查 | 用户选定输出位置、文件探测、看图/视频及需要的试听能力 |
| 预算 | RH币/钱包/自建成本分别记录，余额不等于花费授权，已有授权直接沿用 |

必需项缺失：停止付费生成并说明缺项，不擅自安装/重启或切换方法。可省略项缺失：只执行定义的on_missing回退，在生成前报告notice，例如不会叠加Logo和卖点字幕。文件编码/下载失败不是内容合格，也不是重新生成视频的理由。

## 技术记录

capabilities.json每项verified需真实provider和evidence；环境身份与检查时间绑定当前接入。混合本地/云端流程分别保留证据，不用主视频端报告证明超分端可用。跨端传输和结果回收按原任务记录执行。

```text
avp workflow-check --file WORKFLOW.json --settings project/settings.json --capabilities project/capabilities.json --environment project/environment.json --report project/preflight.json
```

settings.json是固定执行参数的任务快照，不是用户选项。configuration.execution_locked=true时，运行不得改变任何生产值；旧全局/流程默认不再影响成品配方，冲突的直接覆盖被拒绝。预算、源图和最终质量仍是独立关口。

报告missing_capabilities、skipped_steps及pre_run_notices；Agent必须在付费生成前向用户说清缺项与实际交付影响。Go核对声明和记录，不自动判断画面或安装组件。ComfyUI的prepare绑定当前项目、图、spec与实际节点；RH仍沿RH自身执行/预算回执机制。参数、服务器或图改变需重新核验，已有ID恢复原任务。

环境检查记录24小时内且backend/profile/base_url匹配才复用，不只改时间。接入清单setup-status和关闭提醒不能代替本次模型/步骤检查。只做单项能力时按该技巧自身需求检查，不强制整套广告流程；临时制作仍须明确执行位置、输入、输出和预算。

RH检查由Agent读取包内图和平台资料完成；公共目录未枚举H3权重不自动判缺失，不让用户代查模型或先提供H3工作流链接。按[RH接入规则](integrations/runninghub.md)区分模型信息不足、真实服务拒绝和RH接入未完成的一次性工作流编号准备。

## 本次制作数量

按[数量与预算](workflows/delivery-quantity.md)确认需要几个成品，可附预算上限。每条固定包含审查报告，不询问审查/返修模式，不自动付费返修。此规则优先于本文一般性返修顺序和“仅交合格片”的描述，内容问题如实交付报告；技术失败不计完成数。

生图必须按[当前实际工具校验](integrations/image-and-materials.md)确认可调用工具和参考图输入；不能只有verified标记或从RH视频连接推定。

商品宣传的实际试听不是生成或交付的必需门槛。当前工具无法试听时，保留生成原音轨，完成画面、商品和技术审查，在HTML报告中标明“声音待试听”；不因此停止制作、复制独立流程或额外索取批准，也不能声称声音已通过。

本次执行接入按[选择与提示配置](workflows/integration-selection.md)管理：默认每次确认，只有用户明确不再询问才保存关闭项与有效绑定；在接入确定前不进入素材收集，不以历史绑定跳过。

## 核心出片与可选增强

本流程以生成并交付可播放模型视频为目标。只有影响核心出片的必要接入、生成模型/节点、必需输入或文件输出条件缺失才停止。超分、额外场景生图、品牌字幕叠加、试听及额外审查工具均按已有能力尽量完成；缺少或失败就跳过，不让用户选功能开关、不要求复制流程批准，也不擅自安装或另付费补服务。原商品图可直接用于REF时，额外生图缺失不妨碍制作。

每条仍交付一份HTML报告，说明实际做了什么、未做什么、真实缺失/失败原因和启用需要补的服务/模型/节点/预算。未做的检查标待审，不虚构通过。超分不可用时交付生成分辨率原片即为成品，不将2K作为必达门槛；已超分才另附原片。现有可播放原片不能因为增强失败被扣住或被当作没出片。

提醒/记住接入属于可持久配置；增强是工作流的自动适配行为，不新加一组用户配置菜单。内部配置记录预期增强及真实跳过原因，不能通过旧fixed.upscale=true或delivery目标2K把增强重新提升为核心门槛。


## 收素材前的宿主生图检查

选择本次接入后、索取商品素材前，同时检查服务器生成能力和当前会话的参考生图能力。workflow-server-check只验证服务器节点/模型，不是全部前检通过；其host_checks_pending须由Agent按当前真实工具定义或已绑定图像服务完成核验。生图Skill已安装、视频服务器接通、历史会话曾能生图都不算证据。

Agent检查当前实际工具/服务是否可调用、是否支持参考图，记录image.generate.reference的provider、tool、available_now、supports_reference_images及evidence。此时只核验，不生成收费测试图，也无需先索要素材。对用户简短说明“参考生图可用，将补充分镜图”，或“参考生图不可用，本次使用商品原图和文字分镜；启用需补充……”。未核验不得说整套工作流已检查通过。缺少可选生图仍可完成此检查并走原图REF回退；不能把未经检查写成不可用。
